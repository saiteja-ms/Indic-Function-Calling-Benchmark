You are building a function-calling benchmark dataset in the style
of the Berkeley Function Calling Leaderboard (BFCL).

Your task: Generate a JSON array of tool schemas for the
eNAM (National Agriculture Market) mandi price discovery service
on the UMANG app.

The number of tools should be sufficient (typically 10–14 tools)
to cover all realistic farmer and trader interactions and edge cases.

---

## CORE OBJECTIVE

Design tools that enable realistic workflows such as:
- Fetching commodity prices across mandis
- Searching mandis by location
- Comparing prices across regions
- Viewing historical price trends
- Filtering by commodity, quality, and date
- Discovering best price (decision support)
- Viewing arrival quantities and demand trends
- Accessing mandi details and timings
- Grievance handling

---

## CRITICAL DOMAIN CONSTRAINTS (MUST BE ENCODED IN DESCRIPTIONS)

- Authentication is OPTIONAL:
  Price discovery is public.
  Authentication is required only for preferences and grievances.

- Location specificity:
  Prices are mandi-specific.
  Queries must include state/district/mandi.

- Commodity standardization:
  Only supported commodities can be queried.

- Price variation:
  Prices depend on:
    - mandi
    - quality grade
    - arrival quantity
    - date/time

- Real-time limitation:
  Prices may be delayed depending on mandi updates.

- Historical data limitation:
  Historical trends are limited to available records.

- Informational system ONLY:
  These tools do NOT execute buying/selling transactions.

- Grievances should ONLY be raised after verifying price or mandi data.

---

## STATE TRANSITION REQUIREMENT (MANDATORY)

Tool descriptions MUST encode valid data query states:

- query_state:
  invalid_query → valid_query → filtered → aggregated

- data_availability:
  not_found → partial_data → complete_data

Tools must define:
- when queries are valid
- when results may be empty or partial

---

## EDGE CASE REQUIREMENT (MANDATORY)

The toolset MUST support scenarios where:
- invalid commodity name
- unsupported mandi/location
- no price data available
- partial data (some mandis missing)
- conflicting filters (e.g., wrong date range)
- empty results
- stale/outdated prices
- ambiguous queries (multiple mandis with same name)

Descriptions must explicitly reflect these cases.

---

## ERROR HANDLING REQUIREMENT (MANDATORY)

Each tool description MUST include:
- validation rules (commodity, location, time range)
- failure conditions (no data, invalid filters)
- ambiguity handling (multiple matches)

Tools must NOT assume successful data retrieval.

---

## SCENARIO COVERAGE REQUIREMENT (MANDATORY)

The toolset MUST support:
- farmer checking current mandi prices
- comparing prices across mandis
- identifying best mandi to sell
- analyzing historical price trends
- handling missing or invalid data scenarios
- grievance escalation

---

## TOOL DESIGN REQUIREMENTS

- Naming format: enam_verb_noun (lowercase, underscores only)
- Each tool must represent ONE atomic API
- Tools should be independent (no chaining logic required)

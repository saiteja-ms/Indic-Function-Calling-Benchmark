You are building a function-calling benchmark dataset
in the style of the Berkeley Function Calling Leaderboard
(BFCL) and tau-bench.

Your task: Generate tool schemas for the eNAM
(Electronic National Agriculture Market) service
on the UMANG app.

eNAM is the unified national online trading platform
for agricultural commodities connecting farmers,
traders, FPOs, and mandis across India. It enables
farmers to list produce lots, receive bids from
traders across mandis, track payments, and raise
disputes — all through the UMANG interface.

Generate AS MANY tools as needed for complete coverage.
Minimum 14, no upper limit. If a realistic farmer
workflow needs an additional tool not listed below,
add it.

THREE-AXIS EVALUATION DESIGN (CRITICAL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This benchmark evaluates LLMs on three independent
dimensions. The tool set MUST support test cases at
every meaningful cell of this 3-axis grid.

AXIS 1 — Conversation length:
  single-turn  : one user message
  multi-turn   : multiple user messages with state
                 evolving between them

AXIS 2 — Tool calls per turn:
  single-step  : exactly one tool call per turn
  multi-step   : multiple tool calls in the same turn
                 (parallel or parallel-multiple)

AXIS 3 — Task type:
  simple             : one clear tool, unambiguous
  parallel-multiple  : multiple tools called together,
                       no inter-call dependency
  irrelevance        : no tool can answer; model must
                       not call anything

To support all three axes, the tool set MUST include:

PUBLIC TOOLS (no session_token required) — at least 5:
  Price lookups and mandi information are public.
  Enable single-turn, single-step, simple test cases.

PARALLEL-SAFE TOOL PAIRS — at least 4 pairs:
  Tools that read disjoint state and never mutate
  shared fields. Enable parallel-multiple cases.
  Natural pairs:
  - get_commodity_price for two different commodities
  - get_mandi_details + get_commodity_arrivals
  - get_price_history + get_price_trend
  - get_lot_status + get_payment_status

CHAIN-CAPABLE TOOLS — at least 6:
  Tools whose parameter signatures or preconditions
  imply a required prior call. Enable multi-turn
  chain cases. The required prior call is inferred
  from the parameter signature, NOT from text in
  the description.

DOMAIN-BOUNDARY CLARITY:
  The tool set must NOT cover PM-KISAN income support,
  PMFBY crop insurance, MSP procurement at FCI godowns,
  fertilizer subsidy, soil health cards, weather
  forecasting, or KCC loans — these belong to other
  UMANG services and enable irrelevance test cases.

FORBIDDEN — these will invalidate the benchmark:

  ✗ Saying "must be preceded by X" where X is a

  ✗ Saying "followed by Y" where Y is a tool name

ALLOWED — these are the ONLY ways to encode chain order:
  ✓ Parameter signatures
    (a tool requiring session_token implicitly
     requires a prior authentication call)
  ✓ Abstract state preconditions

  ✓ Return value schemas
    ("returns lot_id, assigned_mandi_id, and
     auction_start_time")
  ✓ Description of what state the tool reads or
    mutates, expressed abstractly

The model being evaluated must INFER chain order from
parameter and return schemas — never read it from prose.

DOMAIN CONSTRAINTS (encode abstractly in descriptions)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

These are real eNAM rules — encode them as
preconditions in tool descriptions without naming
which other tools must satisfy them.

- A farmer must be registered on eNAM with a valid
  Aadhaar-linked account before creating lots.
- Produce lots must be weighed at the mandi
  before grading.
- Grading must be completed by an accredited assayer
  before a lot can be listed for auction.
- Auction is open for a fixed window (typically
  30-60 minutes); bids are sealed during the window.
- A lot can only be listed at the mandi where it
  was physically deposited.
- Payment must be made within T+1 working day
  after sale confirmation.
- Disputes about payment can only be raised after
  sale_status: confirmed.
- A lot cannot be relisted once auction_status
  is completed.
- Price data is sourced from Agmarknet and updated
  daily at mandi close.
- MSP is the floor price; lots cannot be sold below
  MSP for notified commodities.

Each tool description must contain (in order):

1. WHAT IT DOES — one sentence stating the action

2. STATE PRECONDITIONS — abstract conditions that
   must hold before this tool can succeed
   (e.g. "requires lot_status: graded and
    listing_status: not_listed")
   NEVER name other tools.

3. INPUT VALIDATION — what makes inputs invalid
   (e.g. "mandi_id must be a registered eNAM mandi;
    commodity_code must be in the Agmarknet registry;
    weight_quintals must be greater than 0")

4. RETURNS — key fields in the success response
   (e.g. "returns lot_id, assigned_mandi_id,
    auction_start_time, and reserve_price")

5. WHAT IT DOES NOT DO — at least one limitation
   (e.g. "does not accept bids; does not transfer
    physical custody of the produce")

6. FAILURE CONDITIONS — at least one rejection scenario
   (e.g. "fails if the lot is already listed, if
    grading is pending, if the commodity is not
    traded at the assigned mandi, or if the listing
    window for the auction date is closed")

You are building a function-calling benchmark dataset
in the style of the Berkeley Function Calling Leaderboard
(BFCL) and tau-bench.

Your task: Generate tool schemas for the Agri Marketing
(Farmer Producer Organisation buy/sell platform) service
on the UMANG app.

This service enables individual farmers and FPOs
(Farmer Producer Organisations) to buy agricultural
inputs (seeds, fertilizers, pesticides, equipment)
and sell produce directly to buyers, processors, and
exporters — bypassing traditional mandi intermediaries.
It covers buyer-seller matching, order management,
logistics coordination, and payment settlement.

This usecase is DISTINCT from eNAM (which is mandi
auction-based) and from MSP procurement (which is
government purchase at floor price). This covers
private market direct trade between farmers/FPOs
and buyers.

Generate AS MANY tools as needed for complete coverage.
Minimum 14, no upper limit. If a realistic farmer
workflow needs an additional tool not listed below,
add it.

THREE-AXIS EVALUATION DESIGN (CRITICAL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This benchmark evaluates LLMs on three independent
dimensions. The tool set MUST support test cases at
every meaningful cell of this 3-axis grid.

AXIS 1 — Conversation length:
  single-turn  : one user message
  multi-turn   : multiple user messages with state
                 evolving between them

AXIS 2 — Tool calls per turn:
  single-step  : exactly one tool call per turn
  multi-step   : multiple tool calls in the same turn
                 (parallel or parallel-multiple)

AXIS 3 — Task type:
  simple             : one clear tool, unambiguous
  parallel-multiple  : multiple tools called together,
                       no inter-call dependency
  irrelevance        : no tool can answer; model must
                       not call anything

To support all three axes, the tool set MUST include:

PUBLIC TOOLS (no session_token required) — at least 4:
  Buyer/seller discovery and commodity listings are
  public. Enable single-turn, single-step, simple
  test cases.

PARALLEL-SAFE TOOL PAIRS — at least 4 pairs:
  Tools that read disjoint state and never mutate
  shared fields. Enable parallel-multiple cases.
  Natural pairs:
  - search_buyers + search_input_suppliers
  - get_commodity_listing + get_buyer_profile
  - get_order_status + get_payment_status
  - get_logistics_status + get_order_status

CHAIN-CAPABLE TOOLS — at least 6:
  Tools whose parameter signatures or preconditions
  imply a required prior call. Enable multi-turn
  chain cases. The required prior call is inferred
  from the parameter signature, NOT from text in
  the description.

DOMAIN-BOUNDARY CLARITY:
  The tool set must NOT cover eNAM mandi auctions,
  MSP procurement at government godowns, PM-KISAN
  income support, PMFBY crop insurance, fertilizer
  DBT subsidy, weather forecasting, or soil health
  cards — these belong to other UMANG services and
  enable irrelevance test cases.

DOMAIN CONSTRAINTS (encode abstractly in descriptions)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

These are real Agri Marketing platform rules — encode
them as preconditions in tool descriptions without
naming which other tools must satisfy them.

- A seller must have a verified profile with Aadhaar
  linkage before creating listings.
- Buyers must be registered and verified on the
  platform before an order can be placed with them.
- A listing must be active (not expired or cancelled)
  for an order to be placed.
- Logistics must be arranged before physical delivery
  can occur; the platform coordinates pickup from
  the farm gate.
- Payment is escrow-based: buyer deposits funds
  before pickup; funds released to seller after
  delivery confirmation.
- A dispute can only be raised after an order has
  been confirmed (order_status: confirmed).
- FPO aggregation allows multiple small farmers
  to pool produce under one listing.
- Input procurement orders follow the same order
  lifecycle as produce sell orders.
- Price negotiation is allowed only before an order
  is confirmed.
- Order cancellation is allowed only before
  logistics are arranged.

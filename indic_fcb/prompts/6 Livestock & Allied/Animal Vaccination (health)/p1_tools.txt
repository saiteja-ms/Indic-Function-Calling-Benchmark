You are building a function-calling benchmark dataset in the style
of the Berkeley Function Calling Leaderboard (BFCL).

Your task: Generate a JSON array of tool schemas for the
Animal Vaccination (livestock health management)
service on the UMANG app.

The number of tools should be sufficient (typically 12–16 tools)
to cover all realistic farmer interactions and edge cases.

---

## CORE OBJECTIVE

Design tools that enable realistic workflows such as:
- Farmer authentication
- Livestock registration
- Vaccination schedule retrieval
- Booking vaccination services
- Tracking vaccination status
- Disease-specific vaccination advisory
- Vaccination history tracking
- Missed vaccination handling
- Field worker visit scheduling
- Grievance handling

---

## CRITICAL DOMAIN CONSTRAINTS (MUST BE ENCODED IN DESCRIPTIONS)

- Authentication is REQUIRED:
  Aadhaar + OTP verification must be completed.
  Authentication returns a session_token.

- Livestock registration dependency:
  Vaccination services require registered livestock.

- Species dependency:
  Vaccination schedules vary by:
    - cattle
    - buffalo
    - sheep
    - goat
    - poultry

- Disease-specific vaccination:
  Vaccines are administered based on disease type
  (e.g., FMD, Brucellosis, PPR).

- Time-based schedule:
  Vaccination must follow:
    - periodic schedules
    - age-specific timelines

- Missed vaccination:
  Missed schedules may require rescheduling or restart.

- Field execution:
  Vaccination must be performed by authorized personnel.

- Verification requirement:
  Vaccination must be recorded after administration.

- No self-administration:
  Farmers cannot directly administer vaccines via the system.

- Grievances should ONLY be raised after checking vaccination or service status.

---

## STATE TRANSITION REQUIREMENT (MANDATORY)

Tool descriptions MUST encode valid state transitions:

- livestock_status:
  not_registered → registered → verified

- vaccination_status:
  not_scheduled → scheduled → administered → missed → rescheduled

- service_status:
  not_requested → requested → assigned → completed → failed

- advisory_status:
  not_generated → generated → updated

Tools must define:
- when actions are valid
- when actions are invalid

## EDGE CASE REQUIREMENT (MANDATORY)

The toolset MUST support scenarios where:
- livestock not registered but vaccination requested

- missed vaccination window
- duplicate vaccination attempt
- incorrect livestock details
- service delay or no field worker assigned
- vaccination not recorded after administration
- incorrect vaccination history
- emergency disease outbreak requiring immediate vaccination

Descriptions must explicitly reflect these cases.

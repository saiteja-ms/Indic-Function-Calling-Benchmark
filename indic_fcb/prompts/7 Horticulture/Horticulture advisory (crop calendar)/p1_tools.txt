You are building a function-calling benchmark dataset in the style
of the Berkeley Function Calling Leaderboard (BFCL).

Your task: Generate a JSON array of tool schemas for the
Horticulture Advisory (Crop Calendar and cultivation guidance)
service on the UMANG app.

The number of tools should be sufficient (typically 10–14 tools)
to cover all realistic farmer interactions and edge cases.

---

## CORE OBJECTIVE

Design tools that enable realistic workflows such as:
- Farmer authentication (optional for personalization)
- Selecting crop and region
- Retrieving crop calendar (stage-wise schedule)
- Getting stage-specific advisory (sowing, irrigation, harvesting)
- Weather-aware advisory adjustments
- Pest and disease advisory
- Fertilizer and input recommendations
- Crop stage tracking
- Seasonal planning
- Grievance handling

---

## CRITICAL DOMAIN CONSTRAINTS (MUST BE ENCODED IN DESCRIPTIONS)

- Public vs personalized access:
  - General advisory is PUBLIC
  - Personalized advisory requires authentication

- Region dependency:
  Advisory depends on:
    - state/district
    - agro-climatic zone

- Crop dependency:
  Advisory must match selected crop.

- Time dependency:
  Crop calendar depends on:
    - season (kharif, rabi, zaid)
    - current date or growth stage

- Stage-based advisory:
  Guidance must be linked to crop stages:
    - land preparation
    - sowing
    - vegetative
    - flowering
    - harvesting

- Weather dependency:
  Advisory may change based on:
    - rainfall
    - temperature
    - extreme weather

- Dynamic advisory:
  Recommendations are NOT static; they vary by:
    - stage
    - region
    - conditions

- No execution guarantee:
  Advisory does NOT guarantee yield or outcomes.

- Grievances should ONLY be raised after checking advisory outputs.

---

## STATE TRANSITION REQUIREMENT (MANDATORY)

Tool descriptions MUST encode valid state transitions:

- advisory_status:
  not_requested → generated → updated → outdated

- crop_stage:
  not_started → sowing → vegetative → flowering → harvesting → completed

- planning_status:
  not_planned → planned → in_progress → completed

Tools must define:
- when advisory is valid
- when advisory is outdated or invalid

---

## EDGE CASE REQUIREMENT (MANDATORY)

The toolset MUST support scenarios where:
- invalid or unsupported crop
- missing or incorrect location
- advisory requested outside season
- mismatch between crop and region
- outdated crop stage information
- weather conditions conflicting with advisory
- ambiguous farmer input (no crop specified)
- incorrect stage selection
- conflicting advisory sources
- unrealistic expectations from advisory

Descriptions must explicitly reflect these cases.

---

## ERROR HANDLING REQUIREMENT (MANDATORY)

Each tool description MUST include:
- validation rules (crop, region, stage)
- rejection conditions (invalid input, unsupported scenario)
- failure scenarios (no advisory available, outdated data)

Tools must NOT assume success-only execution.

---

## SCENARIO COVERAGE REQUIREMENT (MANDATORY)

The toolset MUST support:
- retrieving crop calendar
- getting stage-specific advisory
- adjusting advisory based on weather
- tracking crop stage
- planning seasonal activities
- handling invalid or missing inputs
- grievance escalation

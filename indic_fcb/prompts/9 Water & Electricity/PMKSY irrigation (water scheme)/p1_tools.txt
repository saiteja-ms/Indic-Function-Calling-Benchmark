You are building a function-calling benchmark dataset in the style
of the Berkeley Function Calling Leaderboard (BFCL).

Your task: Generate a JSON array of tool schemas for the
PMKSY (Pradhan Mantri Krishi Sinchai Yojana)
irrigation and micro-irrigation support service on the UMANG app.

The number of tools should be sufficient (typically 12–16 tools)
to cover all realistic farmer interactions and edge cases.

---

## CORE OBJECTIVE

Design tools that enable realistic workflows such as:
- Farmer authentication
- Checking irrigation scheme eligibility
- Selecting irrigation type (drip, sprinkler, canal support)
- Applying for irrigation support/subsidy
- Tracking application status
- Installation tracking (micro-irrigation systems)
- Monitoring irrigation usage
- Water availability tracking
- Efficiency advisory (water optimization)
- Grievance handling

---

## CRITICAL DOMAIN CONSTRAINTS (MUST BE ENCODED IN DESCRIPTIONS)

- Authentication is REQUIRED:
  Aadhaar + OTP verification must be completed.
  Authentication returns a session_token.

- Eligibility dependency:
  Farmer must satisfy:
    - land ownership or operational holding
    - crop suitability
    - region-specific eligibility

- Irrigation type dependency:
  Scheme includes:
    - drip irrigation
    - sprinkler irrigation
    - surface irrigation support

- Water source dependency:
  Irrigation depends on:
    - groundwater availability
    - canal systems
    - local water bodies

- Subsidy dependency:
  Subsidy is provided ONLY for:
    - approved irrigation systems
    - verified installation

- Installation requirement:
  Irrigation system must be installed before usage tracking.

- Efficiency objective:
  Scheme promotes:
    - water conservation
    - optimized irrigation usage

- Resource limitation:
  Water availability may vary due to:
    - seasonal conditions
    - regional scarcity

- No guaranteed water supply:
  System does NOT guarantee water availability.

- Grievances should ONLY be raised after checking application or irrigation status.

---

## STATE TRANSITION REQUIREMENT (MANDATORY)

Tool descriptions MUST encode valid state transitions:

- application_status:
  not_applied → submitted → under_review → approved → rejected

- installation_status:
  not_started → in_progress → installed → verified → operational

- irrigation_status:
  not_active → active → optimized → inefficient

- water_availability_status:
  unavailable → limited → available

- subsidy_status:
  not_initiated → pending → approved → disbursed → failed

Tools must define:
- when actions are valid
- when actions are invalid

---

## EDGE CASE REQUIREMENT (MANDATORY)

The toolset MUST support scenarios where:
- farmer not eligible but applies
- unsuitable crop or land for irrigation type
- water source not available
- installation delay or incomplete setup
- irrigation system installed but not functioning
- inefficient water usage detected
- subsidy not disbursed after installation
- incorrect irrigation configuration
- seasonal water shortage
- mismatch between water availability and irrigation demand

Descriptions must explicitly reflect these cases.

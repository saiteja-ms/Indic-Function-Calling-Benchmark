You are building a function-calling benchmark dataset
in the style of the Berkeley Function Calling Leaderboard
(BFCL) and tau-bench.

Your task: Generate tool schemas for the PMFBY Loss
Claim (post-disaster crop damage claim under Pradhan
Mantri Fasal Bima Yojana) service on the UMANG app.

This usecase covers the POST-ENROLLMENT claim lifecycle
under PMFBY — after a farmer has already enrolled and
paid premium. It covers loss notification, claim
submission, surveyor assignment tracking, yield
assessment, compensation calculation, and grievance
handling for disputed claims.

This usecase is DISTINCT from PMFBY enrollment
(covered in Cluster 1 — that covers premium
calculation and policy issuance). This covers
ONLY the claim side: what happens after a crop
loss event occurs.

It is also DISTINCT from SDRF/NDRF (Cluster 4,
Usecase 1) — SDRF is government relief funded by
taxes; PMFBY is insurance compensation funded by
premiums. A farmer may be eligible for both for the
same loss event.

Generate AS MANY tools as needed for complete coverage.
Minimum 14, no upper limit. If a realistic farmer
workflow needs an additional tool not listed below,
add it.

This benchmark evaluates LLMs on three independent
dimensions. The tool set MUST support test cases at
every meaningful cell of this 3-axis grid.

AXIS 1 — Conversation length:
  single-turn  : one user message
  multi-turn   : multiple user messages with state
                 evolving between them

AXIS 2 — Tool calls per turn:
  single-step  : exactly one tool call per turn
  multi-step   : multiple tool calls in the same turn
                 (parallel or parallel-multiple)

AXIS 3 — Task type:
  simple             : one clear tool, unambiguous
  parallel-multiple  : multiple tools called together,
                       no inter-call dependency
  irrelevance        : no tool can answer; model must
                       not call anything

To support all three axes, the tool set MUST include:

PUBLIC TOOLS (no session_token required) — at least 4:
  Loss event notifications, claim window status,
  and area yield data are public. Enable single-turn,
  single-step, simple test cases.

PARALLEL-SAFE TOOL PAIRS — at least 4 pairs:
  Tools that read disjoint state and never mutate
  shared fields. Enable parallel-multiple cases.
  Natural pairs:
  - get_loss_event_notifications + get_claim_window_status
  - get_claim_status + get_survey_status
  - get_compensation_details + get_payment_status
  - get_area_yield_data + get_loss_event_notifications

CHAIN-CAPABLE TOOLS — at least 6:
  Tools whose parameter signatures or preconditions
  imply a required prior call. Enable multi-turn
  chain cases. The required prior call is inferred
  from the parameter signature, NOT from text in
  the description.

DOMAIN-BOUNDARY CLARITY:
  The tool set must NOT cover PMFBY enrollment
  (premium calculation, application submission —
  covered in Cluster 1), SDRF/NDRF government
  relief, PM-KISAN income support, MSP procurement,
  eNAM mandi trade, or weather forecasting — these
  belong to other UMANG services and enable
  irrelevance test cases.

DOMAIN CONSTRAINTS (encode abstractly in descriptions)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

These are real PMFBY claim rules — encode them as
preconditions in tool descriptions without naming
which other tools must satisfy them.

- Loss notification must be submitted within 72
  hours of the loss event for localised calamity;
  for widespread calamity the window extends to
  the official notification date.
- A formal claim can only be submitted after a
  loss notification has been accepted.
- An active policy (policy_status: active) must
  exist for the crop, season, and plot.
- Surveyor assignment is mandatory for localised
  calamity claims; widespread calamity uses
  area-yield approach via CCE data.
- Compensation = (Threshold Yield - Actual Yield)
  / Threshold Yield × Sum Insured; paid only when
  actual yield falls below threshold.
- Compensation is disbursed via DBT to the bank
  account used for premium payment.
- A claim can be disputed within 30 days of
  compensation decision.
- Duplicate claims for the same policy and loss
  event are rejected.
- A grievance about compensation requires the
  specific claim_id and the disputed
  compensation amount.
- For loanee farmers, compensation may be
  credited to the lending bank account first.

You are building a function-calling benchmark dataset
in the style of the Berkeley Function Calling Leaderboard
(BFCL) and tau-bench.

Your task: Generate tool schemas for the iFMS
(Integrated Fertilizer Management System) service
on the UMANG app.

iFMS manages the end-to-end fertilizer subsidy
disbursement chain in India. Under the Direct Benefit
Transfer for Fertilizers (DBT-F) scheme, subsidy is
transferred directly to fertilizer manufacturers and
retailers. Farmers purchase fertilizers at subsidised
prices by authenticating with Aadhaar at point-of-sale
(PoS). On UMANG, farmers can check subsidised fertilizer
prices, locate nearby authorized retailers, view their
purchase history, track DBT subsidy credit status,
raise grievances for wrong charges or unavailability,
and check nutrient-based subsidy rates.

Generate AS MANY tools as needed for complete coverage.
Minimum 14, no upper limit. If a realistic farmer
workflow needs an additional tool not listed below,
add it.

This benchmark evaluates LLMs on three independent
dimensions. The tool set MUST support test cases at
every meaningful cell of this 3-axis grid.

AXIS 1 — Conversation length:
  single-turn  : one user message
  multi-turn   : multiple user messages with state
                 evolving between them

AXIS 2 — Tool calls per turn:
  single-step  : exactly one tool call per turn
  multi-step   : multiple tool calls in the same turn
                 (parallel or parallel-multiple)

AXIS 3 — Task type:
  simple             : one clear tool, unambiguous
  parallel-multiple  : multiple tools called together,
                       no inter-call dependency
  irrelevance        : no tool can answer; model must
                       not call anything

To support all three axes, the tool set MUST include:

PUBLIC TOOLS (no session_token required) — at least 5:
  Fertilizer price lookup, retailer finder, and
  subsidy rate information are public. Enable
  single-turn, single-step, simple test cases.

PARALLEL-SAFE TOOL PAIRS — at least 4 pairs:
  Tools that read disjoint state and never mutate
  shared fields. Enable parallel-multiple cases.
  Natural pairs:
  - get_fertilizer_price + find_authorized_retailer
  - get_subsidy_rate + get_fertilizer_price
  - get_purchase_history + get_subsidy_credit_status
  - find_authorized_retailer for two different
    fertilizer types simultaneously

CHAIN-CAPABLE TOOLS — at least 5:
  Tools whose parameter signatures or preconditions
  imply a required prior call. Enable multi-turn
  chain cases. The required prior call is inferred
  from the parameter signature, NOT from text in
  the description.

DOMAIN-BOUNDARY CLARITY:
  The tool set must NOT cover PM-KISAN income support,
  PMFBY crop insurance, soil health cards, eNAM mandi
  trade, MSP procurement, KCC query submission, or
  weather forecasting — these belong to other UMANG
  services and enable irrelevance test cases.

DOMAIN CONSTRAINTS (encode abstractly in descriptions)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

These are real iFMS/DBT-F rules — encode them as
preconditions in tool descriptions without naming
which other tools must satisfy them.

- Subsidy is embedded in the price at PoS; farmers
  do not receive subsidy cash directly — they pay
  the subsidised MRP.
- Purchase requires Aadhaar authentication at the
  PoS device; the transaction is recorded in iFMS.
- MRP is fixed by the government for urea (fully
  controlled); for P&K fertilizers MRP is set by
  companies subject to NBS rates.
- Urea is the only fertilizer with a fully
  government-controlled price (₹242 per 45 kg bag
  as of last revision).
- P&K fertilizer subsidies are per-nutrient under
  NBS scheme; rates are revised quarterly.
- A farmer may purchase any quantity at subsidised
  price; there is no per-farmer purchase cap for
  urea (unlike some state-level restrictions).
- Retailer must be licensed under the Fertilizer
  (Control) Order; unlicensed retailers are not
  in the iFMS database.
- Adulteration complaints are routed to the state
  agriculture department for sample collection and
  testing.
- A complaint about overcharging requires the
  specific transaction_id and retailer_id.
- Subsidy credit to the retailer happens after
  PoS authentication; the farmer's transaction
  record shows subsidy_credit_status.

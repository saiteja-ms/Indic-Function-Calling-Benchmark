You are building a function-calling benchmark dataset in the style
of the Berkeley Function Calling Leaderboard (BFCL).

Your task: Generate a JSON array of tool schemas for the
PM-PRANAM (Promotion of Alternate Nutrients for Agriculture Management)
service on the UMANG app.

The number of tools should be sufficient (typically 10–14 tools)
to cover all realistic farmer interactions and edge cases.

---

## CORE OBJECTIVE

Design tools that enable realistic workflows such as:
- Farmer authentication
- Tracking fertilizer usage (especially urea)
- Checking eligibility for incentive programs
- Recommending alternative fertilizers
- Monitoring reduction in chemical fertilizer usage
- Incentive calculation (indirect / state-driven)
- Awareness and advisory dissemination
- Reporting compliance
- Grievance handling

---

## CRITICAL DOMAIN CONSTRAINTS (MUST BE ENCODED IN DESCRIPTIONS)

- Authentication is REQUIRED for personalized tracking:
  Aadhaar + OTP verification must be completed.
  Authentication returns a session_token.

- Aggregate incentive model:
  PM-PRANAM incentives are primarily calculated at
  state/district level, not purely individual farmer level.

- Behavioral dependency:
  Benefits depend on reduction in urea usage compared to baseline.

- Baseline requirement:
  Historical fertilizer usage must exist to measure reduction.

- Advisory-driven system:
  Scheme promotes:
    - organic fertilizers
    - biofertilizers
    - balanced nutrient usage

- No direct cash transfer:
  Incentives are not directly transferred to farmers in most cases;
  benefits may be indirect (subsidy support, infrastructure, etc.).

- Data dependency:
  Usage tracking may rely on:
    - fertilizer purchase records (iFMS)
    - declared crop patterns

- Compliance requirement:
  Farmers must adhere to recommended usage patterns.

- Grievances should ONLY be raised after checking usage or incentive status.

---

## STATE TRANSITION REQUIREMENT (MANDATORY)

Tool descriptions MUST encode valid state transitions:

- usage_status:
  not_recorded → recorded → analyzed

- compliance_status:
  non_compliant → partially_compliant → compliant

- incentive_status:
  not_eligible → eligible → calculated → allocated

- advisory_status:
  not_requested → generated → updated → obsolete

Tools must define:
- when actions are valid
- when actions are invalid

---

## EDGE CASE REQUIREMENT (MANDATORY)

The toolset MUST support scenarios where:
- no baseline data available
- farmer not reducing urea usage
- excessive or imbalanced fertilizer usage
- mismatch between crop and fertilizer recommendation
- incorrect or missing usage data
- attempting to claim direct benefit (not supported)
- conflicting data from purchase vs declared usage
- partial compliance scenarios
- outdated advisory applied
- state-level incentive not applicable to individual farmer

Descriptions must explicitly reflect these cases.

---

## ERROR HANDLING REQUIREMENT (MANDATORY)

Each tool description MUST include:
- validation rules (usage data availability, crop linkage)
- rejection conditions (no reduction, non-compliance)
- failure scenarios (data mismatch, invalid advisory)

Tools must NOT assume success-only execution.

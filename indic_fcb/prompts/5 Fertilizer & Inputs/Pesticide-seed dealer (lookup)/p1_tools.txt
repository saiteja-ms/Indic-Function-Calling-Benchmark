You are building a function-calling benchmark dataset in the style
of the Berkeley Function Calling Leaderboard (BFCL).

Your task: Generate a JSON array of tool schemas for the
Pesticide and Seed Dealer Lookup service on the UMANG app.

The number of tools should be sufficient (typically 10–14 tools)
to cover all realistic farmer interactions and edge cases.

---

## CORE OBJECTIVE

Design tools that enable realistic workflows such as:
- Searching for nearby pesticide/seed dealers
- Filtering dealers by location, crop, or product type
- Verifying dealer authenticity and license status
- Checking product availability (seeds/pesticides)
- Viewing dealer details (contact, address, license)
- Comparing dealers
- Safety and compliance checks
- Grievance handling

---

## CRITICAL DOMAIN CONSTRAINTS (MUST BE ENCODED IN DESCRIPTIONS)

- Public vs authenticated access:
  - Dealer lookup is PUBLIC
  - Saving preferences, history, and grievances REQUIRE authentication

- Location dependency:
  Dealer search MUST include location (village/district/state).
  Queries without location are INVALID.

- Licensing requirement:
  Dealers must have valid government-issued licenses.
  Unlicensed dealers must be flagged as invalid.

- Product regulation:
  Certain pesticides are regulated and require proper authorization.

- Availability uncertainty:
  Product availability is dynamic and may not be guaranteed.

- Crop-product compatibility:
  Seeds/pesticides must match crop type.

- Duplicate listings:
  Same dealer may appear multiple times due to data inconsistencies.

- Safety advisory:
  Tools must emphasize safe usage and compliance.

- Grievances should ONLY be raised after verifying dealer details.

---

## STATE TRANSITION REQUIREMENT (MANDATORY)

Tool descriptions MUST encode valid state transitions:

- query_state:
  invalid_query → valid_query → results_found / no_results

- dealer_status:
  active → inactive → suspended

- license_status:
  valid → expired → suspended

- inventory_status:
  available → limited → unavailable

Tools must define:
- when results are valid
- when results are unreliable or unavailable

---

## EDGE CASE REQUIREMENT (MANDATORY)

The toolset MUST support scenarios where:
- missing or invalid location
- no dealers found in region
- dealer with expired or suspended license
- product not available at dealer
- mismatch between crop and product
- duplicate or conflicting dealer entries
- ambiguous dealer names
- incorrect contact details
- regulated pesticide without authorization
- stale or outdated inventory data

Descriptions must explicitly reflect these cases.

---

## ERROR HANDLING REQUIREMENT (MANDATORY)

Each tool description MUST include:
- validation rules (location required, valid filters)
- failure conditions (no results, invalid dealer)
- ambiguity handling (duplicate or conflicting entries)

Tools must NOT assume successful retrieval.

---

## SCENARIO COVERAGE REQUIREMENT (MANDATORY)

The toolset MUST support:
- farmer searching for nearby dealers
- filtering dealers by product or crop
- verifying dealer license
- checking product availability
- comparing multiple dealers
- handling no-result scenarios
- grievance escalation

---

- Each tool must represent ONE atomic API

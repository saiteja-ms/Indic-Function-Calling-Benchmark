THREE-AXIS EVALUATION DESIGN (CRITICAL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This benchmark evaluates LLMs on three independent
dimensions. The tool set MUST support test cases at
every meaningful cell of this 3-axis grid.

AXIS 1 — Conversation length:
  single-turn  : one user message
  multi-turn   : multiple user messages with state
                 evolving between them

AXIS 2 — Tool calls per turn:
  single-step  : exactly one tool call per turn
  multi-step   : multiple tool calls in the same turn
                 (parallel or parallel-multiple)

AXIS 3 — Task type:
  simple             : one clear tool, unambiguous
  parallel-multiple  : multiple tools called together,
                       no inter-call dependency
  irrelevance        : no tool can answer; model must
                       not call anything

To support all three axes, the tool set MUST include:

PUBLIC TOOLS (no session_token required) — at least 6:
  Kisan Suvidha is predominantly an information service,
  so MOST tools should be public lookups. Enable
  single-turn, single-step, simple test cases.

PARALLEL-SAFE TOOL PAIRS — at least 5 pairs:
  Tools that read disjoint state and never mutate
  shared fields. Enable parallel-multiple cases.

CHAIN-CAPABLE TOOLS — at least 4:
  Tools whose parameter signatures or preconditions
  imply a required prior call. Enable multi-turn
  chain cases. The required prior call is inferred
  from the parameter signature, NOT from text in
  the description.

DOMAIN-BOUNDARY CLARITY:
  The tool set must NOT cover PM-KISAN income support,
  PMFBY crop insurance enrollment, PM-KUSUM solar pumps,
  soil sample collection (separate scheme), eNAM mandi
  trade execution, or fertilizer subsidy DBT — these
  belong to other UMANG services and enable irrelevance
  test cases.

DOMAIN CONSTRAINTS (encode abstractly in descriptions)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

These are real Kisan Suvidha rules — encode them as
preconditions in tool descriptions without naming
which other tools must satisfy them.

- Weather data is sourced from IMD and updated every
  3 hours; forecasts extend 5 days ahead.
- Market prices are sourced from Agmarknet and updated
  daily; weekends and mandi holidays return last-known
  values.
- Advisory content is published by ICAR / state KVK
  network and is district-and-crop specific.
- Subscriptions are delivered via SMS (default), voice
  call (regional language), or push notification.
- A farmer profile must include at least one crop
  and a verified location (district + village) to
  receive personalised advisories.
- Plant protection advisories are stage-specific
  (sowing, vegetative, flowering, ripening) and
  depend on the farmer's reported sowing date.
- Cold-wave and heat-wave alerts use IMD trigger
  thresholds; alerts are pre-emptive (48-72 hours).
- Mandi prices are reported per quintal in INR for
  declared varieties only.
- The system does NOT confirm sales, place orders, or
  transact — it is read-only advisory.
- A grievance about a wrong advisory requires the
  specific advisory_id and date the advisory was
  received.

THREE-AXIS EVALUATION — STRUCTURAL DEFINITIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AXIS 1 — conversation_length:
  single_turn = exactly one user message in
                the conversation
  multi_turn  = two or more user messages

AXIS 2 — tool_calls_per_turn:
  single_step = every ground_truth turn has
                at most ONE tool_call
  multi_step  = at least one ground_truth turn
                has TWO or more tool_calls

AXIS 3 — task_type:
  simple              = at most one tool call
                        per turn AND no
                        irrelevance pattern
  parallel_multiple   = multiple tool calls in
                        one turn AND those calls
                        target DIFFERENT tools
  irrelevance         = ALL ground_truth turns
                        have null_call: true AND
                        at least one has an
                        irrelevance_reason

NOTE: parallel (same tool, different params,
multiple calls in one turn) maps to task_type
"simple" — the multi-step nature is captured
by AXIS 2, not AXIS 3. parallel_multiple is
reserved for DIFFERENT tools called together.

WHAT IS AN INTENT

An intent carries:
  - three-axis position
  - state_preconditions
  - state_transition (reads + writes)
  - compatible_archetypes

State preconditions + transitions are the
SPECIFICATION for stub_logic.py to implement.

── SIMPLE ──────────────────────────────────────────

One intent per tool minimum.

── MULTIPLE ────────────────────────────────────────

Distractor traps — each appears twice with
different user phrasings.

A distractor trap is two tools that would
plausibly seem to solve the SAME user request
but only ONE is correct.

  TRAP A: "I have a specific problem with my
          paddy crop"
    Correct  : atma_submit_expert_query
    Distractor: atma_get_advisory_bulletin
    Trap: bulletin is general advisory for the
    district; expert query is for a specific
    problem needing personalised response.

  TRAP B: "what training programmes are
          available next month"
    Correct  : atma_get_available_trainings
    Distractor: atma_get_demonstration_schedule
    Trap: trainings are formal indoor/classroom
    programmes; demonstrations are field
    visits to model plots.

  TRAP C: "I want to attend the upcoming
          rice training"
    Correct  : atma_register_for_training
    Distractor: atma_get_available_trainings
    Trap: register is the action of enrolling;
    get_available is the lookup of options.

  TRAP D: "how do I get my training certificate"
    Correct  : atma_download_training_certificate
    Distractor: atma_confirm_training_attendance
    Trap: download is for an already-issued
    certificate; confirm is a prerequisite step
    that triggers issuance.

  TRAP E: "the agriculture officer never
          answered my query"
    Correct  : atma_raise_grievance
    Distractor: atma_track_query_response
    Trap: grievance escalates a service failure;
    track only shows current status without
    escalation.

  TRAP F: "what is the recommended pest
          management for cotton bollworm"
    Correct  : atma_get_ipm_advisory
    Distractor: atma_get_advisory_bulletin
    Trap: IPM advisory is pest-specific
    integrated pest management; bulletin is
    general crop guidance.

  TRAP G: "I want to visit the demonstration
          plot in my block"
    Correct  : atma_schedule_farm_school_visit
    Distractor: atma_get_demonstration_schedule
    Trap: schedule_visit is the action of
    booking; get_demo_schedule is the lookup
    of when demonstrations happen.

── PARALLEL ────────────────────────────────────────

Same-tool simultaneous calls. The intent has
multiple calls to ONE tool in a single turn:
  - find_nearest_kvk for two districts
  - get_advisory_bulletin for two crops
  - get_ipm_advisory for two pest categories
  - get_available_trainings for two months
  - track_grievance_status for two IDs

── PARALLEL_MULTIPLE ───────────────────────────────

Different-tool simultaneous calls. The intent
has calls to MULTIPLE DIFFERENT tools in a
single turn, with no dependency between them:
  - find_nearest_kvk + get_sms_contact
  - get_advisory_bulletin + get_ipm_advisory
  - get_available_trainings +
    get_demonstration_schedule
  - get_technology_package +
    get_advisory_bulletin
  - get_agro_climatic_zone +
    get_technology_package

STRICT: never pair tools where one depends on
the other's output.

── TASK_IRRELEVANCE ────────────────────────────────

Topics where no ATMA tool applies:
  - weather forecast for next week (Kisan
    Suvidha or Meghdoot)
  - soil test scheduling or soil sample
    collection (SHC scheme)
  - mandi prices for crops (eNAM or Kisan
    Suvidha)
  - PM-KISAN installment status
  - fertilizer subsidy DBT (iFMS)
  - PMFBY crop insurance enrollment
  - PM-KUSUM solar pump application
  - buying seeds at a registered dealer (PSD
    usecase)
  - MSP procurement token booking
  - cattle vaccination scheduling
  - lightning alerts (Damini)

── BASE ────────────────────────────────────────────

Multi-turn chains. chain_order_enforced: true.

  CHAIN A — Profile registration to training
            registration
    domain_constraint: "training registration
    requires a verified farmer profile in the
    ATMA system"
    Order: authenticate →
           register_farmer_profile →
           get_available_trainings →
           register_for_training

  CHAIN B — Expert query submission and
            tracking
    domain_constraint: "expert query requires
    a verified farmer profile before it can
    be assigned to a specialist"
    Order: authenticate →
           register_farmer_profile →
           submit_expert_query →
           track_query_response

  CHAIN C — Training completion and certificate
    domain_constraint: "certificate is issued
    only after attendance is confirmed by the
    training coordinator"
    Order: authenticate →
           get_available_trainings →
           register_for_training →
           confirm_training_attendance →
           download_training_certificate

  CHAIN D — Farm school visit
    domain_constraint: "farm school visit
    scheduling requires a verified profile"
    Order: authenticate →
           register_farmer_profile →
           schedule_farm_school_visit

  CHAIN E — Grievance flow
    domain_constraint: "grievance requires a
    submitted query to file against"
    Order: authenticate →
           track_query_response →
           raise_grievance

── MISS_PARAM ──────────────────────────────────────

Parameters commonly omitted:
  - district missing from KVK lookup
  - crop missing from advisory bulletin
  - training_id missing from registration
  - query_text missing from expert query
  - visit_date missing from farm school
    schedule
  - otp missing from authentication
  - crop_stage missing from IPM advisory
  - pest_category missing from IPM advisory

── MISS_FUNC ───────────────────────────────────────

Actions ATMA genuinely cannot perform — no
tool exists for these:

  - register for a training programme that
    is cancelled (no override mechanism)
  - download a training certificate before
    attendance is confirmed (no early
    issuance)
  - submit an expert query without a
    registered farmer profile (system blocks)
  - schedule a farm school visit without a
    verified profile (profile prerequisite)
  - submit a 4th open query when 3 are
    already open (3-query limit per farmer)
  - reopen a closed query (no reopen
    function; must submit new query)
  - issue a certificate retroactively for a
    training never attended (no retroactive
    issuance)
  - request advisory in a language not
    supported for the district (system has
    fixed language coverage per district)

── LONG_CONTEXT ────────────────────────────────────

One long_context intent per base chain (5 total).
Each has 3-5 padding user turns BEFORE the chain
begins. Padding turns have tool_calls: [] and
null_call: true.

COMPATIBLE ARCHETYPE GUIDANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Compatibility uses ONLY archetype attributes
from persona.json. NEVER use state fields as
filters. Always reference archetypes by their
canonical ID (ARC_01 to ARC_16). Do NOT invent
descriptive IDs.

MORE COMPATIBLE for ATMA:
  - scheme_experience: repeat_beneficiary or
    aware_of_details (informed users benefit
    most from extension services)
  - landholding_category: small, medium, large
    (more to gain from technology packages
    and IPM advisory)
  - knowledge_of_scheme: aware_of_basics or
    aware_of_details (the service requires
    some background understanding)

LESS COMPATIBLE:
  - digital_literacy: level_5 archetypes
    (often bypass extension services using
    private channels)
  - knowledge_of_scheme: unaware archetypes
    for complex base chains (still valid for
    simple lookups)

FORCED COMPATIBLE:
  - digital_literacy level_1 and level_2
    archetypes MUST appear in find_nearest_kvk
    and get_advisory_bulletin intents (these
    are the most common low-literacy use cases
    via CSC operators)
  - farmer_category: tenant or sharecropper
    archetypes CAN appear (ATMA does not
    require land ownership unlike PMFBY or
    SHC scheme) — include them in regular
    intents, not only miss_func

PROCESS for picking compatible archetypes:
  1. Open persona.json
  2. For each of ARC_01 through ARC_16, check:
     - landholding_category
     - farmer_category
     - region
     - digital_literacy
     - scheme_experience
     - knowledge_of_scheme
  3. Apply rules above to decide compatibility
  4. List archetype_id values (ARC_XX format)

Every archetype must appear in at least 3 intents
across all categories.

You are building a function-calling benchmark dataset in the style
of the Berkeley Function Calling Leaderboard (BFCL).

Your task: Generate a JSON array of tool schemas for the
Crop Advisory (ATMA - Agricultural Technology Management Agency)
service on the UMANG app.

The number of tools should be sufficient (typically 10–14 tools)
to cover all realistic farmer interactions and edge cases.

---

## CORE OBJECTIVE

Design tools that enable realistic workflows such as:
- Fetching crop-specific advisories
- Stage-based farming recommendations
- Weather-based advisory guidance
- Pest and disease diagnosis
- Fertilizer and irrigation recommendations
- Crop planning support
- Expert consultation requests
- Advisory history tracking
- Grievance handling

---

## CRITICAL DOMAIN CONSTRAINTS (MUST BE ENCODED IN DESCRIPTIONS)

- Authentication is REQUIRED for personalized advisory:
  Aadhaar + OTP verification must be completed.
  Authentication returns a session_token.

- Location dependency:
  Advisory depends on district/state/agro-climatic zone.

- Crop specificity:
  Advisory must be tied to a specific crop.

- Growth stage dependency:
  Advisory varies by stage:
    sowing → vegetative → flowering → harvesting

- Weather dependency:
  Advisory must consider current or forecasted weather.

- Diagnosis requirement:
  Pest/disease advisory requires symptoms or structured inputs.

- Advisory limitation:
  Tools provide recommendations ONLY — no direct farm execution.

- Expert escalation:
  Expert consultation should be used when automated advisory is insufficient.

- Grievances should ONLY be raised after attempting advisory retrieval.

---

## STATE TRANSITION REQUIREMENT (MANDATORY)

Tool descriptions MUST encode valid state transitions:

- advisory_state:
  requested → generated → updated → obsolete

- diagnosis_state:
  symptoms_provided → analyzed → diagnosed → recommendation_generated

- consultation_state:
  not_requested → requested → assigned → resolved

Tools must define:
- when advisory is valid
- when advisory becomes outdated

---

## EDGE CASE REQUIREMENT (MANDATORY)

The toolset MUST support scenarios where:
- invalid or unsupported crop
- missing growth stage
- conflicting inputs (crop vs location mismatch)
- insufficient data for diagnosis
- multiple possible diagnoses (ambiguity)
- outdated advisory used
- weather mismatch affecting advisory
- expert not available
- incorrect or irrelevant recommendation

Descriptions must explicitly reflect these cases.

---

## ERROR HANDLING REQUIREMENT (MANDATORY)

Each tool description MUST include:
- validation rules (crop, stage, location required)
- failure conditions (insufficient input, no advisory available)
- ambiguity handling (multiple diagnoses or advisories)

Tools must NOT assume successful advisory generation.

---

## SCENARIO COVERAGE REQUIREMENT (MANDATORY)

The toolset MUST support:
- farmer requesting advisory for crop
- stage-specific recommendations
- pest/disease diagnosis
- weather-adjusted advisory
- escalation to expert consultation
- handling incorrect or missing advisory
- grievance escalation

---

## TOOL DESIGN REQUIREMENTS

- Naming format: atma_verb_noun (lowercase, underscores only)
- Each tool must represent ONE atomic API
- Tools should be independent (no chaining logic required)

You are building a function-calling benchmark dataset in the style
of the Berkeley Function Calling Leaderboard (BFCL).

Your task: Generate a JSON array of tool schemas for the
CHC (Custom Hiring Centre) Farm Machinery Rental Portal
service on the UMANG app.

The number of tools should be sufficient (typically 12–16 tools)
to cover all realistic farmer interactions and edge cases.

---

## CORE OBJECTIVE

Design tools that enable realistic workflows such as:
- Farmer authentication
- Discovering nearby CHC centres
- Searching available farm machinery
- Checking availability for specific dates/time slots
- Booking machinery
- Scheduling usage
- Tracking booking status
- Cancelling or modifying bookings
- Payment tracking (if applicable)
- Grievance handling

---

## CRITICAL DOMAIN CONSTRAINTS (MUST BE ENCODED IN DESCRIPTIONS)

- Public vs authenticated access:
  - Browsing machinery is PUBLIC
  - Booking requires authentication

- Location dependency:
  Machinery availability depends on:
    - nearest CHC centre
    - region/district

- Time-slot dependency:
  Machinery must be booked for:
    - specific date
    - time duration

- Availability constraint:
  Machinery can be booked ONLY if:
    - available for selected slot
    - not already reserved

- Equipment type:
  Machinery includes:
    - tractor
    - harvester
    - rotavator
    - seed drill
    - sprayer

- Booking lifecycle:
  booking_requested → confirmed → active → completed → cancelled

- Usage constraint:
  Booking duration must not exceed allowed limits.

- Conflict handling:
  Overlapping bookings are NOT allowed.

- Payment dependency:
  Some bookings may require advance payment.

- Grievances should ONLY be raised after checking booking status.

---

## STATE TRANSITION REQUIREMENT (MANDATORY)

Tool descriptions MUST encode valid state transitions:

- booking_status:
  requested → confirmed → active → completed → cancelled → failed

- availability_status:
  available → reserved → unavailable

- payment_status:
  not_initiated → pending → completed → failed

- machinery_status:
  operational → in_use → maintenance → unavailable

Tools must define:
- when actions are valid
- when actions are invalid

---

## EDGE CASE REQUIREMENT (MANDATORY)

The toolset MUST support scenarios where:
- no CHC available in location
- machinery not available for selected time
- overlapping booking attempt
- invalid or past date selection
- excessive booking duration
- machinery under maintenance
- booking cancelled after confirmation
- payment failure
- incorrect booking details
- double booking attempts

Descriptions must explicitly reflect these cases.

---

## ERROR HANDLING REQUIREMENT (MANDATORY)

Each tool description MUST include:
- validation rules (location, availability, time slot)
- rejection conditions (invalid booking, overlap conflict)
- failure scenarios (payment failure, booking failure)

Tools must NOT assume success-only execution.

---

## SCENARIO COVERAGE REQUIREMENT (MANDATORY)

The toolset MUST support:
- farmer searching machinery
- checking availability
- booking machinery
- modifying or cancelling booking
- tracking usage and booking status
- handling booking conflicts
- grievance escalation

---

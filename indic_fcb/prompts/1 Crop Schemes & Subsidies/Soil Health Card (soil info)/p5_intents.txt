THREE-AXIS EVALUATION — STRUCTURAL DEFINITIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AXIS 1 — conversation_length:
  single_turn = exactly one user message in
                the conversation
  multi_turn  = two or more user messages

AXIS 2 — tool_calls_per_turn:
  single_step = every ground_truth turn has
                at most ONE tool_call
  multi_step  = at least one ground_truth turn
                has TWO or more tool_calls

AXIS 3 — task_type:
  simple              = at most one tool call
                        per turn AND no
                        irrelevance pattern
  parallel_multiple   = multiple tool calls in
                        one turn AND those calls
                        target DIFFERENT tools
  irrelevance         = ALL ground_truth turns
                        have null_call: true AND
                        at least one has an
                        irrelevance_reason

NOTE: parallel (same tool, different params,
multiple calls in one turn) maps to task_type
"simple" — the multi-step nature is captured
by AXIS 2, not AXIS 3. parallel_multiple is
reserved for DIFFERENT tools called together.

WHAT IS AN INTENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

An intent carries:
  - three-axis position
  - state_preconditions
  - state_transition (reads + writes)
  - compatible_archetypes

State preconditions + transitions are the
SPECIFICATION for stub_logic.py to implement.

── SIMPLE ──────────────────────────────────────────

One intent per tool minimum.

── MULTIPLE ────────────────────────────────────────

Distractor traps — each appears twice with
different user phrasings.

A distractor trap is two tools that would
plausibly seem to solve the SAME user request
but only ONE is correct.

  TRAP A: "where is my soil sample right now"
    Correct  : shc_get_sample_status
    Distractor: shc_get_test_status
    Trap: sample status is logistics location;
    test status is lab processing.

  TRAP B: "is my soil health card ready yet"
    Correct  : shc_get_test_status
    Distractor: shc_get_soil_health_card
    Trap: get_card retrieves the card; user
    wants to KNOW if it is ready first.

  TRAP C: "what fertilizer should I use for
          my paddy field"
    Correct  : shc_get_fertilizer_recommendation
    Distractor: shc_get_soil_health_card
    Trap: card shows nutrient levels;
    recommendation is the actionable advice
    derived from those levels.

  TRAP D: "I disagree with my soil test results"
    Correct  : shc_request_retest
    Distractor: shc_raise_grievance
    Trap: retest is the formal dispute
    mechanism; grievance is for service
    complaints not technical disputes.

  TRAP E: "where can I get my soil tested in
          my district"
    Correct  : shc_get_nearby_labs
    Distractor: shc_get_lab_assignment
    Trap: nearby_labs is informational lookup;
    assignment is for an already-collected
    sample.

  TRAP F: "when can I request a soil sample
          collection"
    Correct  : shc_get_sampling_window
    Distractor: shc_request_sample_collection
    Trap: window is informational about timing;
    request is the action of asking for one.

  TRAP G: "compare my new card to last year's"
    Correct  : shc_compare_historical_cards
    Distractor: shc_get_soil_health_card
    Trap: get_card returns one card; compare
    returns trend across cycles.

── PARALLEL ────────────────────────────────────────

Same-tool simultaneous calls. The intent has
multiple calls to ONE tool in a single turn:
  - get_sample_status for two plot IDs
  - get_test_status for two sample IDs
  - get_nearby_labs for two districts
  - track_grievance_status for two IDs
  - get_fertilizer_recommendation for two crops

── PARALLEL_MULTIPLE ───────────────────────────────

Different-tool simultaneous calls. The intent
has calls to MULTIPLE DIFFERENT tools in a
single turn, with no dependency between them:
  - get_sample_status + get_lab_assignment
  - get_test_status + get_lab_assignment
  - get_nearby_labs + get_sampling_window
  - validate_land_records + get_sampling_window
  - get_soil_health_card +
    get_fertilizer_recommendation

STRICT: never pair tools where one depends on
the other's output.

── TASK_IRRELEVANCE ────────────────────────────────

Topics where no SHC scheme tool applies:
  - PM-KISAN income support installments
  - PMFBY crop insurance enrollment
  - PM-KUSUM solar pump application
  - fertilizer subsidy DBT (iFMS)
  - mandi price lookup (eNAM)
  - weather forecast (Kisan Suvidha)
  - crop sowing advisory (ATMA / Kisan Suvidha)
  - eNAM trading
  - MSP procurement
  - cattle or livestock advisory
  - reading specific soil nutrient values for
    fertilizer planning (that is the SHC portal
    usecase, available only AFTER a card is
    issued through this scheme)

── BASE ────────────────────────────────────────────

Multi-turn chains. chain_order_enforced: true.

  CHAIN A — New plot registration to sample
            request
    domain_constraint: "plot must be registered
    and verified before sample collection can
    be requested, and sampling window must be
    open"
    Order: authenticate → validate_land_records →
           register_plot → get_sampling_window →
           request_sample_collection

  CHAIN B — Sample to card retrieval
    domain_constraint: "card is issued only
    after test is completed"
    Order: authenticate → get_sample_status →
           get_test_status → get_soil_health_card

  CHAIN C — Retest flow
    domain_constraint: "retest can be requested
    only within 15 days of completed test"
    Order: authenticate → get_sample_status →
           get_test_status → request_retest

  CHAIN D — Grievance flow
    domain_constraint: "grievance requires a
    sample record to file against"
    Order: authenticate → get_sample_status →
           raise_grievance

── MISS_PARAM ──────────────────────────────────────

Parameters commonly omitted:
  - plot_id missing from sample request
  - sample_id missing from test status check
  - card_id missing from card retrieval
  - district missing from nearby labs lookup
  - crop missing from fertilizer recommendation
  - otp missing from authentication
  - land_area missing from plot registration
  - irrigation_type missing from sample request

── MISS_FUNC ───────────────────────────────────────

Actions SHC scheme genuinely cannot perform —
no tool exists for these:

  - request sample collection when sampling
    window is closed (system blocks; no
    out-of-cycle requests)
  - request a second sample for the same plot
    in the same cycle (one card per plot per
    cycle rule)
  - request retest after the 15-day dispute
    window has passed (window-based, no
    extension)
  - retrieve a card before test is completed
    (no early issuance)
  - compare historical cards when only one
    card exists for the plot (system needs at
    least two cycles)
  - register a plot owned by another person
    (ownership verification required)
  - retrieve a card for a plot not registered
    to this farmer (no cross-farmer access)
  - request expedited test processing (no
    priority lane in the scheme)

── LONG_CONTEXT ────────────────────────────────────

One long_context intent per base chain (4 total).
Each has 3-5 padding user turns BEFORE the chain
begins. Padding turns have tool_calls: [] and
null_call: true.

Compatibility uses ONLY archetype attributes
from persona.json. NEVER use state fields as
filters. Always reference archetypes by their
canonical ID (ARC_01 to ARC_16). Do NOT invent
descriptive IDs.

MORE COMPATIBLE for SHC scheme:
  - landholding_category: small, medium, large
    (higher need for soil testing)
  - farmer_category: owner (plot registration
    requires ownership)
  - irrigation_type: rain_fed (highest soil
    data need due to nutrient depletion)
  - scheme_experience: aware_of_basics or
    higher
  - all regions (SHC is nationwide)

LESS COMPATIBLE:
  - farmer_category: tenant or sharecropper
    for plot registration intents (land is
    not in their name)

FORCED COMPATIBLE:
  - tenant/sharecropper archetypes MUST appear
    in miss_func intents (cannot register
    plot without ownership)
  - digital_literacy level_1 archetypes MUST
    appear in simple and multiple intents
    (low-literacy use cases via CSC)

PROCESS for picking compatible archetypes:
  1. Open persona.json
  2. For each of ARC_01 through ARC_16, check:
     - landholding_category
     - farmer_category
     - region
     - irrigation_type
     - digital_literacy
     - scheme_experience
  3. Apply rules above to decide compatibility
  4. List archetype_id values (ARC_XX format)

Every archetype must appear in at least 3 intents
across all categories.

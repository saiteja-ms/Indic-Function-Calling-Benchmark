You are building a function-calling benchmark dataset in the style
of the Berkeley Function Calling Leaderboard (BFCL).

Your task: Generate a JSON array of tool schemas for the
PMFBY (Pradhan Mantri Fasal Bima Yojana - crop insurance)
service on the UMANG app.

The number of tools should be sufficient (typically 12–16 tools)
to cover all realistic farmer interactions and edge cases.

---

## CORE OBJECTIVE

Design tools that enable realistic workflows such as:
- Farmer authentication
- Policy enrollment for a crop season
- Premium calculation and payment
- Policy status tracking
- Crop loss reporting
- Claim submission and processing
- Survey and assessment tracking
- Claim approval/rejection
- Compensation payout tracking
- Grievance handling

---

## CRITICAL DOMAIN CONSTRAINTS (MUST BE ENCODED IN DESCRIPTIONS)

- Authentication is REQUIRED:
  Aadhaar + OTP verification must be completed.
  Authentication returns a session_token.

- Enrollment window:
  Farmers can enroll ONLY within a predefined season window.

- Crop and land linkage:
  Insurance must be tied to:
    - specific crop
    - specific land parcel

- Premium rules:
  Farmer pays only a portion of premium; rest is subsidized.

- Claim dependency:
  Claims can be filed ONLY if:
    - policy is active
    - crop loss event has occurred

- Loss types:
  Claims can be triggered by:
    - drought
    - flood
    - pest attack
    - cyclone
    - unseasonal rainfall

- Survey dependency:
  Claim approval depends on:
    - field survey
    - remote sensing / official assessment

- Partial vs full loss:
  Compensation depends on severity of loss.

- Payment flow:
  Claim must be approved before compensation is processed.

- Grievances should ONLY be raised after checking claim or policy status.

---

## STATE TRANSITION REQUIREMENT (MANDATORY)

Tool descriptions MUST encode valid state transitions:

- policy_status:
  not_enrolled → enrolled → active → expired

- claim_status:
  not_reported → reported → under_review → approved → rejected → compensated

- payment_status:
  pending → initiated → completed → failed

- survey_status:
  not_started → in_progress → completed

Tools must define:
- when actions are valid
- when actions are invalid

---

## EDGE CASE REQUIREMENT (MANDATORY)

The toolset MUST support scenarios where:
- farmer tries to enroll after deadline
- invalid crop or unsupported region
- policy not active but claim attempted
- duplicate enrollment attempt
- incorrect land-crop mapping
- claim without valid loss event
- multiple claims for same loss
- survey delay or missing report
- claim rejection due to insufficient loss
- partial compensation disputes
- payment delay or failure

Descriptions must explicitly reflect these cases.

---

## ERROR HANDLING REQUIREMENT (MANDATORY)

Each tool description MUST include:
- validation rules (season window, eligibility)
- rejection conditions (invalid enrollment, no active policy)
- failure scenarios (claim rejection, payment failure)

Tools must NOT assume success-only execution.

---

## SCENARIO COVERAGE REQUIREMENT (MANDATORY)

The toolset MUST support:
- farmer enrolling for insurance
- calculating and paying premium

- claim approval and compensation
- claim rejection scenarios

THREE-AXIS EVALUATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AXIS 1 — conversation_length:
  single_turn = exactly one user message in
                the conversation
  multi_turn  = two or more user messages

AXIS 2 — tool_calls_per_turn:
  single_step = every ground_truth turn has
                at most ONE tool_call
  multi_step  = at least one ground_truth turn
                has TWO or more tool_calls

AXIS 3 — task_type:
  simple              = at most one tool call
                        per turn AND no
                        irrelevance pattern
  parallel_multiple   = multiple tool calls in
                        one turn AND those calls
                        target DIFFERENT tools
  irrelevance         = ALL ground_truth turns
                        have null_call: true AND
                        at least one has an
                        irrelevance_reason

NOTE: parallel (same tool, different params,
multiple calls in one turn) maps to task_type
"simple" in the 3-axis grid — the multi-step
nature is captured by AXIS 2, not AXIS 3.
parallel_multiple is reserved for DIFFERENT
tools called together.

── SIMPLE ──────────────────────────────────────────

One intent per tool minimum.

── MULTIPLE ────────────────────────────────────────

Distractor traps — each appears twice with
different user phrasings.

A distractor trap is two tools that would
plausibly seem to solve the SAME user request
but only ONE is correct.

  TRAP A: "am I eligible for PM-KUSUM"
    Correct  : pmkusum_check_eligibility
    Distractor: pmkusum_validate_land_records
    Trap: land validation is one input to
    eligibility, but eligibility check is the
    user's actual goal.

  TRAP B: "what subsidy will I get"
    Correct  : pmkusum_calculate_subsidy
    Distractor: pmkusum_get_subsidy_disbursement_status
    Trap: calculation is for pre-application;
    disbursement is post-approval status.

  TRAP C: "how much pump can I afford"
    Correct  : pmkusum_get_pump_capacity_options
    Distractor: pmkusum_calculate_subsidy
    Trap: user wants capacity choices; subsidy
    calculation comes after capacity is chosen.

  TRAP D: "which vendor should I pick"
    Correct  : pmkusum_get_empanelled_vendors
    Distractor: pmkusum_select_vendor
    Trap: user wants to BROWSE vendors;
    selection is the action after browsing.

  TRAP E: "my installed pump is broken"
    Correct  : pmkusum_report_pump_issue
    Distractor: pmkusum_raise_grievance
    Trap: report_pump_issue is for technical
    faults; grievance is for service complaints.

  TRAP F: "when will my pump be installed"
    Correct  : pmkusum_get_installation_schedule
    Distractor: pmkusum_get_application_status
    Trap: schedule is for installation date;
    application status is approval lifecycle.

  TRAP G: "how do I pay my share of the cost"
    Correct  : pmkusum_pay_farmer_share
    Distractor: pmkusum_calculate_subsidy
    Trap: user wants to PAY; calculation is
    pre-application step.

── BASE ────────────────────────────────────────────

Multi-turn chains. chain_order_enforced: true.

  CHAIN A — New Component B application flow
    domain_constraint: "subsidy can be calculated
    only after eligibility is confirmed, vendor
    can be selected only after application is
    approved, farmer share can be paid only
    after vendor is confirmed"
    Order: authenticate → check_eligibility →
           validate_land_records →
           calculate_subsidy → submit_application →
           get_empanelled_vendors → select_vendor →
           pay_farmer_share

  CHAIN B — Application status and installation
    domain_constraint: "installation schedule
    is available only after application is approved"
    Order: authenticate → get_application_status →
           get_installation_schedule

  CHAIN C — Post-installation pump issue
    domain_constraint: "pump issue can be
    reported only after installation is completed"
    Order: authenticate → get_application_status →
           report_pump_issue

  CHAIN D — Subsidy disbursement tracking
    domain_constraint: "disbursement status is
    available only after application is approved"
    Order: authenticate → get_application_status →
           get_subsidy_disbursement_status

  CHAIN E — Grievance flow
    domain_constraint: "grievance requires an
    application record to file against"
    Order: authenticate → get_application_status →
           raise_grievance

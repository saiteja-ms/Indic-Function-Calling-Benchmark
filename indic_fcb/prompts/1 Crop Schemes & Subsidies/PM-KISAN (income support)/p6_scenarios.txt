SECTION 1 — CORE PRINCIPLE

A scenario has FOUR parts:
  1. initial_state  — what the stub is seeded with
  2. conversation   — alternating user and
                      ground_truth turns
  3. axes           — DERIVED from the conversation
                      structure (not copied)
  4. expected_final_state — only changed fields

The intent defines the GOAL and the STATE.
The archetype defines the CONVERSATION SHAPE.
The conversation shape determines the AXES.

The archetype's INFORMATION DISCLOSURE attribute
controls how many user turns the conversation has.

upfront_complete:
  Single user turn containing every parameter.
  Even for "miss_param" or "base" category intents,
  this archetype gives everything in one message.

  Conversation length: usually 1 user turn for
    simple/multiple/parallel/parallel_multiple/
    task_irrelevance categories
  For BASE chains (genuinely multi-step):
    still multi-turn because chain order forces it

partial_then_supply:
  Two user turns: first turn describes the problem
  with some identifiers, second turn provides the
  rest after model asks.

  Conversation length: 2 user turns minimum.
  For BASE chains: 2-3 user turns.

reactive_only:
  Three or more user turns: each parameter comes
  in a separate user message after explicit ask.

  Conversation length: 3+ user turns.

SECTION 3 — TURN STRUCTURE (STRICT)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Each turn has TWO entries: one for user, one for
ground_truth — both with the SAME turn_index.

Turn pattern:
  turn 1:
    {speaker: "user",         turn_index: 1, ...}
    {speaker: "ground_truth", turn_index: 1, ...}
  turn 2:
    {speaker: "user",         turn_index: 2, ...}
    {speaker: "ground_truth", turn_index: 2, ...}

Ground truth for a turn is what the model SHOULD
do AFTER reading that turn's user message.

SECTION 4 — GROUND TRUTH RULES PER CATEGORY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The intent's category determines what the
ground truth looks like on each turn.

CATEGORY: simple
  One user turn, one tool call in ground truth.
  null_call: false on every turn.

CATEGORY: multiple
  One user turn, one tool call in ground truth.
  null_call: false.
  The intent's distractor_tools must NOT appear
  in ground truth tool_calls — they are wrong
  options the model must reject.

CATEGORY: parallel
  One user turn, multiple tool_calls in the SAME
  ground_truth turn (calls to the SAME tool with
  different parameters).

CATEGORY: parallel_multiple
  One user turn, multiple tool_calls in the SAME
  ground_truth turn (calls to DIFFERENT tools,
  no dependency between them).

CATEGORY: task_irrelevance
  Every ground_truth turn has:
    tool_calls: []
    null_call: true
    irrelevance_reason: "<which service handles
      this and why PM-KISAN does not>"

CATEGORY: base
  Multi-turn chain with domain-enforced order.
  Each ground_truth turn has exactly one tool call.
  Tools called in the chain order specified by
  the intent's required_tools list.

CATEGORY: miss_param
  Multi-turn. ONE turn has a missing parameter.
  That turn's ground_truth has:
    tool_calls: []
    null_call: true
    model_should_ask_for: "<exact param_name from
      tools.jsonl>"
  The NEXT turn provides the param, and ground
  truth makes the tool call.

CATEGORY: miss_func
  Multi-turn. ONE turn requests an unavailable
  action. That turn's ground_truth has:
    tool_calls: []
    null_call: true
    model_should_decline: "<one sentence why>"

CATEGORY: long_context
  Multi-turn base chain with 3-5 padding user
  turns BEFORE the actual chain begins. Padding
  turns have ground_truth with tool_calls: []
  and null_call: true (model just acknowledges).

SECTION 5 — eval_mode SELECTION (CRITICAL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Every parameter in every tool_call has an
eval_mode. There are exactly THREE options.

  EXACT
    The parameter value must match exactly.
    Use for: all structured identifiers
      (aadhaar_number, mobile_number, otp,
       grievance_id, beneficiary_id,
       transaction_id, application_id,
       ifsc_code, account_number, dates,
       amounts, enum values, booleans)

  SUBSTRING
    The value must appear as a substring.
    Use ONLY for free-text fields:
       complaint_description, grievance_remarks,
       address_details, name (when used in
       search context), resolution_notes

  TYPE_ONLY
    Only the value's type is checked.
    Use ONLY for values the model CANNOT KNOW
    until they are returned by a prior tool
    call within this same conversation.

    The ONLY legitimate use cases:
       session_token (returned by authenticate)
       grievance_id when it was RETURNED by
         raise_grievance in this conversation
       beneficiary_id when it was RETURNED by
         register in this conversation
       transaction_id when RETURNED by a
         payment-initiation tool

DECISION FLOW for eval_mode:

  Step 1: Does the value appear in any user
          message in this conversation?
          YES → cannot be TYPE_ONLY.
                Go to Step 3.
          NO  → Go to Step 2.

  Step 2: Was the value returned by a prior
          tool call within this conversation?
          YES → eval_mode = TYPE_ONLY
          NO  → ERROR. The value must come
                from somewhere. Re-examine
                the scenario.

  Step 3: Is the field a structured identifier
          or fixed value (numbers, dates,
          enums, IDs, booleans)?
          YES → eval_mode = EXACT
          NO  → eval_mode = SUBSTRING (only
                for free-text)

SECTION 6 — AXES DERIVATION (NEVER COPY FROM INTENT)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The axes block is DERIVED from the conversation
you generated. Do NOT copy from the intent.
Compute it as follows:

  conversation_length:
    Count distinct turn_index values where
    speaker == "user".
    If count == 1: "single_turn"
    If count >= 2: "multi_turn"

  tool_calls_per_turn:
    Find max(len(tool_calls)) across all
    ground_truth turns.
    If max > 1: "multi_step"
    Else:       "single_step"

  task_type:
    Let G = list of all ground_truth turns.
    If ALL turns in G have null_call: true
       AND at least one has irrelevance_reason:
         "irrelevance"
    Else if max tool_calls per turn > 1
         AND those calls are to DIFFERENT tools:
         "parallel_multiple"
    Else:
         "simple"
